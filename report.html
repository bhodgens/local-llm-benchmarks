Key Findings

Code Generation vs Agentic Tool Use

  • Ternary-Bonsai-27B (dspark): tau2 DOMINANT at 0.80 (previous best was 0.53) while maintaining solid LCB (62.7%). Best agent model by far, at only 1.71 bits/weight ternary
  • gemma-4-26B-A4B-it-QAT: LCB #1 (89.3%) at 83 tok/s -- the A4B MoE (4B active params) is extremely efficient. Best code-gen quality/speed ratio
  • gemma-4-12B-it-QAT: LCB #2 (86.7%) with tau2 0.47 -- the smaller QAT model is also strong on agent tasks
  • LFM2.5-8B-Coder-v2: Now #2 on tau2 (0.53) -- good agent, mediocre coder (45% LCB)
  • Qwen3.5-9B-DSV4-Flash: Weak at code gen (18.7% LCB) but strong agent (tau2 0.47) -- reasoning distill hurts coding
  • Models that excel at standalone code generation often struggle with conversational tool use, and vice versa. Ternary-Bonsai breaks this pattern: strong at both

Ternary Quantization: 1.71 bpw Is Viable

  • Ternary-Bonsai-27B at 1.71 bits/weight (7.2GB deployed) scores tau2=0.80 and LCB=62.7% -- beating most Q4_K_M models that are 2-3x larger
  • DSpark speculative decoding worked on the PrismML llama.cpp fork (built at ~/git/llama.cpp-prismml), providing lossless 1.34x speedup
  • At 36.3 tok/s on V100 with 262K context, it is practical for production agent workloads
  • Qwen3.6-27B-MTP (Q4_K_M, 17.1GB) scored LCB=53.3% and tau2=0.40 -- the ternary model outperforms the full-precision Q4 across both benchmarks at 1/3 the size

Speed vs Quality Tradeoffs

  • LFM2.5-8B base is the fastest at 213 tok/s -- 6x faster than MoE models -- with decent tau2 (0.46)
  • gemma-4-26B-A4B-it-QAT hits 83 tok/s despite being a "26B" model -- only 4B params active per token via MoE
  • Qwen3.5-9B-DSV4-Flash at 81 tok/s is the fastest 9B model, strong for agent workloads
  • MoE 35B models at 26-28 tok/s are the slowest but competitive on LCB (80-85%)
  • Qwen3.6-27B-MTP at 30 tok/s is slow for a 27B but competitive across benchmarks

Model-Specific Notes

  • Gemma-4 family dominates code generation: 4 of top 5 LCB scores
  • LFM2.5-8B is the best small agentic model (tau2 0.53 at only 31 min)
  • Qwopus3.6-35B MoE is the most balanced: LCB 80% + tau2 0.40
  • RavenX-OpenFable-Holo3 is the best MoE on LCB (85.3%)
  • DeepSeek-R1 scored poorly on LCB (17.3%) -- thinking tokens not fully suppressible
  • Qwen3.6-Abliterated-Heretic is consistently the weakest across all benchmarks
  • DeepSeek-Coder-V2-Lite is surprisingly strong on tau2 (0.50) despite being a coding model
  • IQ3_K_R4 permanently failed (unsupported ggml type 138 quantization in llama.cpp v9836)

- HumanEval: Only Qwen2.5-Coder completed successfully (raw code completion mode). Other models need chat-mode rerun. N/A = not run, not failed.
- LiveCodeBench: 75 problems from latest release, pass@1, temperature=0.0, thinking disabled via enable_thinking=false where supported

- Speed benchmarks are raw decode throughput; actual benchmark throughput varies with prompt processing overhead
